## 17. Контрагенты

### Два типа серверов

Каждая инсталляция SalesDoc работает в одном из двух режимов. **Тип сервера определяется системой автоматически** — интегратор не может выбрать или переключить его через API.

| Тип сервера | Модель учёта |
|-------------|--------------|
| **Обычный сервер** | Классическая одноуровневая модель: каждый **клиент** (торговая точка) сам несёт свои оплаты, баланс и долг. |
| **Сервер контрагентов** | Двухуровневая модель: **контрагент** (плательщик) и его **торговые точки** (клиенты). |

Чтобы понять, с каким сервером вы работаете, ориентируйтесь на поведение методов, описанное ниже: если методы `setContragent` / `getContragent` доступны, а в ответах оплат появляется объект `contragent` — это **сервер контрагентов**.

### Обычный сервер

Всё работает так, как описано в остальных разделах документации. Никаких дополнительных полей и объектов не появляется:

- продажи, оплаты, баланс и долг ведутся по каждому клиенту (торговой точке) отдельно;
- методы `setContragent` и `getContragent` недоступны и возвращают ошибку (см. ниже);
- поле `contragent` в `setClient` также недоступно.

### Сервер контрагентов

Здесь вводится дополнительный уровень — **контрагент**.

- **Контрагент** — это юридическое лицо / плательщик, «компания в счёте-фактуре».
- **Клиенты** — это **торговые точки** (`clients`) контрагента, где фактически происходят продажи.
- **Продажи** идут по торговым точкам, а **деньги, баланс и долг** — по контрагенту.

**Наглядный пример:**

```
ООО «Ромашка»              ← контрагент (плательщик, «компания в счёте-фактуре»)
├── Магазин №1             ← торговая точка (клиент / salepoint)
└── Магазин №2             ← торговая точка (клиент / salepoint)
```

Заказы оформляются на «Магазин №1» и «Магазин №2», а вся финансовая картина (оплаты, баланс, задолженность) сводится к ООО «Ромашка».

**Что меняется в поведении методов на сервере контрагентов:**

- **Оплаты и начальные балансы**, отправленные для клиента (торговой точки), автоматически относятся к контрагенту этого клиента. В ответах при этом возвращаются **оба** объекта: `contragent` идентифицирует **контрагента** (плательщика), а `client` — торговую точку, к которой относилась операция.
- **`getBalance`** агрегирует баланс **по контрагентам** (а не по отдельным торговым точкам).
- **Заказы** автоматически привязываются к контрагенту соответствующей торговой точки.
- У контрагента может **не быть ни одной торговой точки** (самостоятельное юридическое лицо). Такие контрагенты всё равно присутствуют в `getBalance` и `getPayment`.

> **Важно:** конкретные изменения полей описаны в соответствующих разделах:
> - привязка клиента к контрагенту — [`setClient`](07-set-references.md#1017-setclient--создатьобновить-клиентов) (поле `contragent`);
> - атрибуция оплат и объект `contragent` — [`setPayment`](09-finance-photo-extra.md#131-setpayment--создать-оплату), [`getPayment`](02-get-references.md#915-getpayment--оплаты);
> - начальный баланс — [`setBalance`](09-finance-photo-extra.md#132-setbalance--установить-начальный-баланс);
> - агрегация баланса по контрагентам — [`getBalance`](05-get-finance.md#929-getbalance--баланс-клиентов);
> - привязка заказа к контрагенту — [`setOrder`](08-set-warehouse-orders.md#121-setorder--создатьобновить-заказ).

### Доступность методов

Методы `setContragent`, `getContragent` и поле `contragent` метода `setClient` работают **только на сервере контрагентов**. На обычном сервере они возвращают ошибку HTTP 400:

```json
{
    "status": false,
    "result": [],
    "error": {
        "code": 400,
        "message": "Contragent mode is not enabled",
        "data": []
    }
}
```

### 17.1. `setContragent` — Создание/обновление контрагентов

**Описание:** Создание или обновление контрагентов (юридических лиц / плательщиков). Метод доступен **только на сервере контрагентов**; на обычном сервере возвращается ошибка `Contragent mode is not enabled` (HTTP 400).

> **Примечание — две сущности на сервере контрагентов:** **клиент** — это торговая точка, где фактически происходят продажи; **контрагент** — юридическое лицо / плательщик, которому принадлежат торговые точки и на котором учитываются все деньги, баланс и долг.

Данные передаются пакетом в `data.contragent` (действует то же ограничение на размер пакета, что и в остальных SET-методах). Каждый элемент создаётся или обновляется независимо; ответ содержит счётчики `completed` / `error`.

**Запрос:**
```json
{
    "method": "setContragent",
    "auth": { "userId": "d0_1", "token": "..." },
    "data": {
        "contragent": [
            {
                "CS_id": "",
                "SD_id": "",
                "code_1C": "000000500",
                "shortName": "Ромашка",
                "firmName": "ООО «Ромашка»",
                "address": "ул. Амира Темура, 5",
                "orentir": "Напротив банка",
                "tel": "+998901234567",
                "comment": "Ключевой контрагент",
                "inn": "123456789",
                "active": true,
                "lat": 41.2995,
                "lon": 69.2401,
                "category": {
                    "code_1C": "000000001"
                },
                "territory": {
                    "code_1C": "000000001"
                },
                "bankDetails": {
                    "bankName": "Асака банк",
                    "accountNumber": "20208000900123456789",
                    "bankCode": "00444"
                }
            }
        ]
    }
}
```

**Поля элемента:**

| Поле | Тип | Обязательное | Описание |
|------|-----|:---:|----------|
| `CS_id` / `SD_id` / `code_1C` | string | ✅ (один из) | Идентификатор контрагента. Если запись не найдена — создаётся новая (по `code_1C`). |
| `shortName` | string | ❌ | Краткое название |
| `firmName` | string | ❌ | Полное название юридического лица |
| `address` | string | ❌ | Адрес |
| `orentir` | string | ❌ | Ориентир |
| `tel` | string | ❌ | Телефон |
| `comment` | string | ❌ | Комментарий |
| `inn` | string | ❌ | ИНН |
| `active` | bool/string | ❌ | Активность |
| `lat` / `lon` | float | ❌ | GPS-координаты |
| `category` | object | ✅ | Категория клиента — `CS_id` / `SD_id` / `code_1C` |
| `territory` | object | ❌ | Территория (город) — `CS_id` / `SD_id` / `code_1C`. Если не указана или не найдена, подставляется город по умолчанию. |
| `bankDetails` | object | ❌ | Банковские реквизиты |
| `bankDetails.bankName` | string | ❌ | Название банка |
| `bankDetails.accountNumber` | string | ❌ | Расчётный счёт |
| `bankDetails.bankCode` | string | ❌ | МФО / код банка |

> Для вложенных объектов (`category`, `territory`) действует общий порядок поиска: **CS_id → SD_id → code_1C**.

**Ответ:**
```json
{
    "status": true,
    "result": {
        "completed": 1,
        "error": 0,
        "data": {
            "contragent": [
                {
                    "CS_id": "F1-d0_500",
                    "SD_id": "d0_500",
                    "code_1C": "000000500"
                }
            ]
        }
    }
}
```

**Поля ответа:**

| Поле | Тип | Описание |
|------|-----|----------|
| `completed` | int | Количество успешно обработанных контрагентов |
| `error` | int | Количество контрагентов с ошибкой |
| `data.contragent[].CS_id` | string | Внешний идентификатор контрагента (с префиксом филиала) |
| `data.contragent[].SD_id` | string | Серверный ID контрагента |
| `data.contragent[].code_1C` | string | Код контрагента в 1С |

**Ошибки элемента:**

| Сообщение | Причина |
|-----------|---------|
| `Contragent mode is not enabled` | Метод вызван на обычном сервере (HTTP 400 на весь запрос) |
| `Contragent is not found or cannot created` | Контрагент не найден и не может быть создан по переданным идентификаторам |
| `ClientCategory is not found` | Категория (`category`) не найдена |
| `City is not found` | Территория (`territory`) не найдена и город по умолчанию отсутствует |
| ошибки валидации | Модель контрагента не прошла проверку (возвращается объект с ошибками полей) |

> Формат ошибок элемента совпадает с остальными SET-методами: при наличии ошибок ответ приходит с `status: false`, блоком `error` и заполненными счётчиками `completed` / `error`.

### 17.2. `getContragent` — Список контрагентов

**Описание:** Получение списка контрагентов вместе с их торговыми точками (`clients`). Метод доступен **только на сервере контрагентов**; на обычном сервере возвращается ошибка `Contragent mode is not enabled` (HTTP 400).

> **Примечание — две сущности на сервере контрагентов:** **клиент** — это торговая точка, где фактически происходят продажи; **контрагент** — юридическое лицо / плательщик, которому принадлежат торговые точки и на котором учитываются все деньги, баланс и долг.

**Запрос:**
```json
{
    "method": "getContragent",
    "auth": { "userId": "d0_1", "token": "..." },
    "params": {
        "limit": 100,
        "page": 1,
        "filter": {
            "contragent": {
                "code_1C": "000000500",
                "active": "Y"
            },
            "include": "all"
        }
    }
}
```

**Фильтры:**

| Фильтр | Описание |
|--------|----------|
| `filter.contragent.CS_id` / `SD_id` / `code_1C` | Идентификатор конкретного контрагента |
| `filter.contragent.active` | Активность контрагента |
| `filter.include` | Источник записей: `sd`, `1c`, `all` |

**Значения `filter.include`:**

| Значение | Какие записи возвращаются |
|----------|---------------------------|
| `sd` | Только контрагенты, созданные в SalesDoc (без кода 1С) |
| `1c` | Только контрагенты, загруженные из 1С (с кодом 1С) |
| `all` | Все контрагенты |

**Ответ:**
```json
{
    "status": true,
    "result": {
        "contragent": [
            {
                "CS_id": "F1-d0_500",
                "SD_id": "d0_500",
                "code_1C": "000000500",
                "name": "Ромашка",
                "firmName": "ООО «Ромашка»",
                "address": "ул. Амира Темура, 5",
                "waymark": "Напротив банка",
                "tel": "+998901234567",
                "lon": 69.2401,
                "lat": 41.2995,
                "allowKredit": 1,
                "allowConsig": 0,
                "comment": "Ключевой контрагент",
                "photo": null,
                "active": "Y",
                "inn": "123456789",
                "bankDetails": {
                    "bank": "Асака банк",
                    "account": "20208000900123456789",
                    "mfo": "00444"
                },
                "category": {
                    "CS_id": "d0_1",
                    "SD_id": "d0_1",
                    "code_1C": "000000001"
                },
                "city": {
                    "CS_id": "d0_13",
                    "SD_id": "d0_13",
                    "code_1C": "000000001"
                },
                "clients": [
                    {
                        "CS_id": "F1-d0_100",
                        "SD_id": "d0_100",
                        "code_1C": "000000100",
                        "name": "Магазин №1"
                    },
                    {
                        "CS_id": "F1-d0_101",
                        "SD_id": "d0_101",
                        "code_1C": "000000101",
                        "name": "Магазин №2"
                    }
                ]
            }
        ]
    },
    "pagination": { "limit": 100, "total": 1, "page": 1 }
}
```

**Поля ответа:**

| Поле | Тип | Описание |
|------|-----|----------|
| `CS_id` | string | Внешний идентификатор контрагента (с префиксом филиала) |
| `SD_id` | string | Серверный ID контрагента |
| `code_1C` | string | Код контрагента в 1С |
| `name` | string | Краткое название |
| `firmName` | string | Полное название юридического лица |
| `address` | string | Адрес |
| `waymark` | string | Ориентир |
| `tel` | string | Телефон |
| `lon` / `lat` | float | GPS-координаты |
| `allowKredit` | int | Разрешён кредит (`1` / `0`) |
| `allowConsig` | int | Разрешена консигнация (`1` / `0`) |
| `comment` | string | Комментарий |
| `photo` | string\|null | Фото |
| `active` | string | Активность |
| `inn` | string | ИНН |
| **bankDetails** | object | Банковские реквизиты |
| `bankDetails.bank` | string | Название банка |
| `bankDetails.account` | string | Расчётный счёт |
| `bankDetails.mfo` | string | МФО / код банка |
| **category** | object | Категория контрагента (`CS_id`, `SD_id`, `code_1C`) |
| **city** | object | Территория / город (`CS_id`, `SD_id`, `code_1C`) |
| **clients** | array | Торговые точки контрагента |
| `clients[].CS_id` | string | Внешний идентификатор торговой точки |
| `clients[].SD_id` | string | Серверный ID торговой точки |
| `clients[].code_1C` | string | Код торговой точки в 1С |
| `clients[].name` | string | Название торговой точки |

> У контрагента без торговых точек массив `clients` возвращается пустым (`[]`) — такой контрагент всё равно присутствует в списке.
